# STRM 独立源目录与 FIFO 队列设计

**日期**: 2026-05-15  
**状态**: 草案

## 背景

当前 STRM 模块的生成源绑定在 `archive_output_cid` 上，默认链路和归档输出强耦合。用户希望在不改变原有默认行为的前提下，额外提供一个“临时指定源目录”的入口，用于偶尔从别的 115 目录批量生成 STRM。

本次需求有几个明确边界：

- 默认生成链路保持现状
- 指定源目录只用于手动触发，不写入后端运行时配置
- 指定源目录刷新后仍保留，用户可手动清空
- 后端允许提交多个生成任务，但按 FIFO 串行执行
- 同一个指定源目录的重复任务只保留最新一次
- 后端重启后队列清空

## 目标

1. 保留现有默认生成入口和归档输出目录逻辑。
2. 在 STRM 页面新增一个可临时保存的 115 源目录选择器。
3. 支持“指定源生成”的一次性提交，不影响默认生成配置。
4. 将 STRM 生成改为内存队列串行执行，支持 FIFO 排队。
5. 对同一 `source_cid` 的重复指定任务做合并，保留最新请求。

## 非目标

- 不新增任何新的 runtime_settings 持久化字段
- 不改变现有 STRM 扫描、写入、manifest 清理、刷新媒体库逻辑
- 不把队列持久化到数据库或磁盘
- 不做抢占式取消，不会中断正在运行的任务
- 不新增自动切换源目录的调度逻辑

## 用户交互

### 默认生成

- 保持当前 STRM 页面原有默认生成入口
- 点击后仍然使用 `archive_output_cid`
- 对用户来说，默认生成的语义不变

### 指定源生成

- 页面新增一个“指定源目录”选择区
- 选择的是 115 目录 `cid`
- 选择结果仅保存在浏览器本地存储
- 用户刷新页面后仍然保留
- 用户手动清空后恢复为空
- 点击“指定源生成”时，使用当前保存的 `source_cid`

### 排队反馈

- 页面显示当前是否有 STRM 任务在运行
- 页面显示当前队列长度，至少能看到“运行中 / 等待中”的状态
- 手动提交后，前端根据接口返回和轮询状态更新提示

## 前端设计

### 状态存储

- 使用 `localStorage` 保存临时源目录
- 保存内容至少包括 `source_cid` 和 `source_name`
- 不写入后端 runtime_settings

### 页面结构

- 保留现有默认配置区
- 新增“指定源目录”区
- 新增清空按钮
- 新增“指定源生成”按钮

### 交互规则

- 若未选择指定源目录，“指定源生成”按钮置灰或提示先选择目录
- 选择目录后，页面立即展示目录名与 CID
- 点击清空后，删除本地缓存并回到未选择状态
- 默认生成按钮不受该选择影响

## 后端设计

### 任务模型

每次生成提交都创建一个内存任务对象，至少包含：

- `mode`: `default` 或 `source`
- `trigger`: 手动、归档完成自动触发等
- `source_cid`: 指定源时使用
- `source_name`: 仅用于展示
- `output_cid`: 运行时最终扫描目标
- `output_dir`: 本地 STRM 输出目录
- `requested_at`: 提交时间

默认任务在提交时立即解析出 `archive_output_cid`，避免等待期间配置变化导致语义漂移。
默认生成与指定源生成共用同一条队列，只是在任务对象里用 `mode` 区分来源。

### 队列规则

- 使用单 worker 串行消费队列
- 任务按提交顺序 FIFO 执行
- 队列仅驻留内存，后端重启即清空
- 不支持取消正在运行的任务
- 不支持抢占

### 去重规则

- 仅对“指定源生成”做去重
- 同一个 `source_cid` 同时最多保留一个待执行任务
- 新提交的同源任务会替换队列里旧的待执行任务
- 正在运行的任务不取消，只影响后续等待队列

### 接口调整

- `POST /api/strm/generate`
  - 无请求体或空请求体时，表示默认生成并入队
  - 传入 `source_cid/source_name` 时，表示指定源生成并入队
- 返回值建议包含：
  - `queued`
  - `task_mode`
  - `queue_position`
  - `queue_size`
  - `source_cid`
  - `source_name`

### 运行状态

现有 `runtime` 信息保留，并补充：

- 当前运行任务概况
- 队列等待数量
- 最近一次完成/失败任务的模式与源信息

这样前端既能展示“默认生成是否在跑”，也能展示“指定源任务是否在排队”。

## 兼容性

- 默认生成入口不变
- 现有归档输出目录配置不变
- 现有 STRM 扫描和生成逻辑不变
- 新增的临时源目录只影响手动指定生成

## 错误处理

- 未选择源目录就点指定源生成，前端直接拦截
- 选择的 `cid` 失效或无法访问时，任务失败并写入运行日志
- 队列内部异常只影响单个任务，不影响后续任务继续执行

## 测试点

### 后端

- 默认生成仍然使用 `archive_output_cid`
- 指定源生成会使用提交时的 `source_cid`
- 队列按 FIFO 执行
- 同一个 `source_cid` 的重复待执行任务会合并
- 后端重启后队列清空

### 前端

- 刷新页面后能恢复临时源目录
- 手动清空后本地缓存移除
- 默认生成和指定源生成互不干扰
- 运行态能展示队列和执行状态

## 验收标准

- 默认生成行为与当前版本一致
- 用户可以选择一个额外的 115 源目录并单独提交生成
- 刷新页面后该临时选择仍然存在
- 后端不会取消已提交的任务
- 任务执行顺序严格符合 FIFO
- 同源重复提交会被合并为最新一次
